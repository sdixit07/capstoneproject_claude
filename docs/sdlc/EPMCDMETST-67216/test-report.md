            <id>report</id>

- No `<version>` declared - inherited from `spring-boot-starter-parent` 3.4.4 pluginManagement (resolves to 0.8.15).
- No other dependency or plugin version changed.
- No Surefire configuration added or altered; include / exclude behaviour is untouched.
- No `check` goal / coverage rule added, so the build does not fail on coverage; the 85 % gate is
  enforced by this report, not by the build.

## 6. `ProductControllerIT` - never executed, and what it hides

**Confirmed: `ProductControllerIT` is never executed.** `ecom-project/pom.xml` contains no
`maven-surefire-plugin` configuration, so Surefire's default includes apply
(`**/Test*.java`, `**/*Test.java`, `**/*Tests.java`, `**/*TestCase.java`). `ProductControllerIT`
matches none of them, so it is silently skipped - it does not even appear in the `Skipped` count.
This is also why the new tests were deliberately named `*IntegrationTest`
(deviation 1 in `implementation-notes.md`).

**Diagnostic run** (`-Dtest=ProductControllerIT`, executed only to answer this question; coverage
report left untouched, no files modified):

```
[ERROR] Tests run: 13, Failures: 10, Errors: 0, Skipped: 0 -- in org.ecom.productcatalog.controller.ProductControllerIT
[ERROR]   getProducts_sort_price_desc_works:103 JSON path "$[0].price"

[ERROR]   getProducts_nonNumericPrice_returnsBadRequest:198 Status expected:<400> but was:<200>

```

**Does the skip hide a coverage gap relevant to this story? No.**

1. `ProductControllerIT` contains **no test for `GET /api/products/{id}`** at all - it never calls
   `ProductController.getProductById` or `ProductService.getProductById`. Enabling it would add
   nothing to this story's coverage.
2. The three of its tests that would pass (`getProducts_noParams_returnsWholeCatalog`,
   `getProducts_search_filter_works`, `getProductsByCategoryPath_stillWorks`) exercise
   `getAllProducts` and `getProductByCategory`, which are **already at 100 % line and instruction
   coverage** thanks to `ProductByIdIntegrationTest.listAll_unchanged` and
   `.categoryPath_stillReturnsList`. Module coverage would not change.
3. It does hide a different problem, **pre-existing and out of scope for this story**: 10 of its 13
   tests assert search / sort / `minPrice` / `maxPrice` query-parameter behaviour that
   `ProductController.getAllProducts()` does not implement. It is a dead test file written against a
   future (or reverted) feature, and because Surefire skips it the failure is invisible in CI.

**Recommendation (not actioned here - it would mean touching an existing test or Surefire config):**
either delete `ProductControllerIT`, or add `maven-failsafe-plugin` so `*IT` classes run in the
`verify` phase - but only once the price-filter feature it targets exists, otherwise the build breaks.
